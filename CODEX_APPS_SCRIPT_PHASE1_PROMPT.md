## Script Requirements

### Custom Menu

Menu name:
CrewPay Ledger

Menu items:
- Generate Worker Proof
- Log Proof Export
- Log Access Change
- Log Correction
- Create Email-Ready Notice
- About CrewPay Ledger

### Generate Worker Proof

Purpose:
Prepare or refresh the Worker Proof tab for the selected worker and pay period.

Must:
- Read selector cells from Worker Proof.
- Confirm selected worker and selected pay period match.
- Show a warning if they do not match.
- Update generated timestamp if safe.
- Never generate proof for all workers.
- Never expose another worker's records.

### Log Proof Export

Purpose:
Append a row to Proof Exports after proof is generated/exported.

Must write:
- Export ID
- Worker ID
- Worker Name
- Pay Period ID
- Export Type
- Generated At
- Generated By
- Export Reference
- Notes

Must:
- Log worker-specific proof only.
- Use workbook records as source.
- Not export all workers.

### Log Access Change

Purpose:
Append a row to Access Log when a worker access status changes.

Must write:
- Log ID
- Worker ID
- Worker Name
- Previous Status
- New Status
- Changed At
- Changed By
- Reason

Must:
- Preserve history.
- Not delete worker records.
- Not hide inactive worker proof.

### Log Correction

Purpose:
Append a row to Correction Log for visible corrections.

Must write:
- Correction ID
- Entry ID
- Worker ID
- Worker Name
- Pay Period ID
- Correction Date
- Corrected By
- Correction Reason
- Original Value Summary
- New Value Summary
- Notes

Must:
- Make corrections visible.
- Avoid silent overwrite.
- Not change proof without a visible correction record.

### Create Email-Ready Notice

Purpose:
Create/copy email-ready notice text from Admin Notices.

Must:
- Use selected or active Admin Notices row if practical.
- Build clear notice text with subject/message/worker/pay-period context if present.
- Mark or note that the notice is email-ready if practical.
- Not send email.
- Not become chat.
- Not support worker-to-worker messaging.

## Quality Requirements

- Keep code readable and small.
- Use named constants for sheet names.
- Use helper functions for finding columns by header.
- Avoid hardcoding fragile column numbers where practical.
- Add clear comments where setup is needed.
- Provide manual install/use instructions in apps_script/README.md.
- Make scripts safe if a required sheet/header is missing by showing a helpful error.
